# tigris_bucket_lifecycle (Resource)

Provides a Tigris bucket lifecycle configuration resource. Each rule ages or expires objects matching an optional key prefix. Tigris supports a single transition per rule, so multi-tier aging is expressed as one rule per tier.

## Example Usage

```terraform
# Create the bucket
resource "tigris_bucket" "example_bucket" {
  bucket = "my-custom-bucket"
}

# Age and expire objects under the logs/ prefix.
# Tigris allows a single transition per rule, so multi-tier aging is expressed
# as one rule per tier.
resource "tigris_bucket_lifecycle" "example_bucket_lifecycle" {
  bucket = tigris_bucket.example_bucket.bucket

  rule {
    id     = "logs-to-infrequent-access"
    prefix = "logs/"
    status = "Enabled"

    transition {
      days         = 30
      storage_tier = "STANDARD_IA"
    }
  }

  rule {
    id     = "logs-to-archive-then-expire"
    prefix = "logs/"
    status = "Enabled"

    transition {
      days         = 90
      storage_tier = "GLACIER_IR"
    }

    expiration {
      days = 365
    }
  }
}
```

## Tigris Support and Limitations

Tigris implements a subset of the S3 lifecycle API. This resource is scoped to what Tigris accepts:

- A rule has at most one transition. To age objects through more than one tier, use one rule per tier.
- Rules support current-version transitions and expiration only. Noncurrent-version actions and incomplete-multipart-upload cleanup are not supported.
- Rules filter by key prefix only. Object tag filters are not supported.
- Transition tiers are `STANDARD_IA`, `GLACIER`, and `GLACIER_IR`.
- Transition and expiration triggers are specified in `days` only (`0` transitions immediately). Date-based triggers are not supported, and importing a bucket whose lifecycle uses one will fail.
- Each rule must set at least one of `transition` or `expiration`, and rule ids must be unique within the configuration.
